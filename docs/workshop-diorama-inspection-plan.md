## Implementation

1. Build inspection records from the existing presentation model before camera projection. Each record carries a stable ID, canonical name, physical or reference role, world anchor and available extent or boundary, constituents or typed relationships, standing and provenance. Preserve the model's source IDs and frames. Distinguish a modeled surface, a provisional candidate and an acquired record. Add Seat details as presentation metadata alongside `SnailNearMonitor` and use the original geometry points for rendering.
2. Include XT and YT on every inscription, each with FROM, TOWARD and a source or explicit **UNREGISTERED**. Use THIS HERE as the reference for the reported registration. Reuse explicit directed witnesses where their provenance applies, such as the local `XT-TO-XT-zero-to-one` line, and identify the candidate YT inbound probe by its recorded endpoints and status. Keep YT's own HERE and the next Landinging distinct from THIS HERE. The audit found no common physical XT/YT bearing assignment for all objects. Camera angles, coordinate axes, a datum shared by two objects and XT/YT text in an ID supply no missing bearing. Camera sight direction can change and should be described separately as view state.
3. Use the same record binding for scene, locator and flat monitor. Make hover and keyboard focus reveal the name and both bearings directly. Click, tap or Enter toggles an inscription by record ID. Preserve multiple appointments while hover continues to identify other objects. Use accessible selection controls for coincident or occluded records and stable keyboard focus across redraws. Require an inspection record for every physical or reference primitive at emission. Treat UI backgrounds and explanatory captions as presentation elements. Avoid displaying unsupported physical proxies.
4. Keep appointments in the LiveView browser hook independently of orbit, distance and stand. On each redraw, project the original world anchor or a visible portion of its geometry and position a readable label with a leader. Mark clipping, occlusion or absence in the current view in a persistent list with a way to return to the object. Keep the record when a different stand changes visible geometry. A camera marker's leader follows the current camera while its reference identity stays fixed. Keep labels and appointments out of acquisition and replay state.
